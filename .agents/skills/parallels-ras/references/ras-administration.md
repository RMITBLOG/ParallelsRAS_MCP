# RAS administration guide

Read this before changing RAS configuration or taking a live session action. Use the [v21 REST API guide](https://download.parallels.com/ras/v21/en_US/Parallels-RAS-REST-API-Guide-21.pdf) for the exact method, path, query parameters, request body, response, and any Apply step. The method/path catalog is an allowlist, not a schema catalog. `ras_farm_get_version` reports the REST Web Service version and must not be treated as proof of the entire Farm's installed patch level; [Parallels v21 release notes](https://kb.parallels.com/en/131037) can clarify patch behavior.

## Identify the target and effect

1. Resolve the Farm, Site, object type, and object ID with read queries. A host, host pool, provider, published item, and session are different targets. Do not infer an ID from a display name alone.
2. Inspect related configuration and live state. For publishing, check target hosts or pool, resource status, folder hierarchy, and applicable policy. For connectivity, distinguish Gateway, Broker, authentication, and resource-host faults. For maintenance, inspect active sessions before drain, reboot, or logoff.
3. Confirm that the configured RAS administrator has the necessary scope and permissions. RAS roles can limit access by Site, category, or object; `RAS_ENABLE_WRITE=true` exposes the tool but does not grant extra RAS permissions. [Administrator permissions](https://docs.parallels.com/landing/ras-admin-guide/parallels-ras-21-administrators-guide/farm-and-sites/managing-administrator-accounts/administrator-account-permissions)

## Choose and execute the operation

1. Search `ras_write_operations` for the resource and action. It covers documented POST, PUT, and DELETE method/path pairs, excluding the client's own logon and logoff lifecycle. Names that share a prefix can still be different complete operations.
2. Read the exact API endpoint documentation. Use its request schema and examples, not the shape returned by a GET, and respect endpoint-specific query parameters and upload formats. The skill accepts JSON, multipart fields/files, or raw base64 as separate body formats.
3. Send one `ras_write_request` through standard input. The client does not replay writes after `401`, timeouts, or uncertain results. On an ambiguous outcome, read the target state before deciding on another action.
4. Apply settings only when the documented workflow calls for it. Parallels examples show a separate `POST /api/Settings/Apply` for some configuration changes, and the RAS Console likewise has an Apply step. An Apply can activate other staged configuration, so account for shared administration. [Connection Broker and Gateway API sample](https://docs.parallels.com/landing/ras-rest-api-guide/examples/connection-broker-and-secure-gateway-sample), [Broker configuration](https://docs.parallels.com/landing/ras-admin-guide/parallels-ras-21-administrators-guide/ras-connection-broker/configuring-ras-connection-brokers)
5. Verify the intended state through a relevant read query. A successful HTTP status proves the request was accepted, not that every user-facing effect is already visible.

## Operational distinctions

- **Published item removal** removes the RAS published resource, not the underlying application, according to the Administrator's Guide. Folder status can also affect contained resources. [Publishing management](https://docs.parallels.com/landing/ras-admin-guide/parallels-ras-21-administrators-guide/publishing/general-management-tasks)
- **Session actions** such as disconnect, logoff, send message, and process termination affect active users differently. Match the user's requested action exactly and identify the session before acting. [Managing sessions](https://docs.parallels.com/landing/ras-admin-guide/parallels-ras-21-administrators-guide/session-management/managing-sessions)
- **Manual RD Session Host drain** allows reconnections to existing sessions but blocks new client logons. `POST /api/RDS/Host/{id}/Drain` persists through reboot until logons are enabled; `POST /api/RDS/Host/{id}/DrainUntilReboot` ends at restart. Choose the requested lifetime explicitly. The catalog also contains `POST /api/RDS/Host/{id}/EnableLogons` to restore logons after persistent drain. Verify the host state and active sessions before and after. [Host controls](https://docs.parallels.com/landing/ras-mp-guide/v20-en-us/infrastructure/rd-session-hosts/manage-an-rd-session-host/overview), [v21 REST API guide](https://download.parallels.com/ras/v21/en_US/Parallels-RAS-REST-API-Guide-21.pdf)
- **Maintenance and auto-upgrade** may place RD Session Hosts into drain mode; a configured maintenance window can also force logoff. Inspect active sessions and pool maintenance settings first. [RD Session Host agent upgrades](https://docs.parallels.com/landing/ras-admin-guide/parallels-ras-21-administrators-guide/rd-session-hosts/manage-rd-session-hosts/manage-host-pools-rd-session-hosts/upgrading-agents-rd-session-hosts)
- The **RAS REST API** used by this skill is distinct from the optional **Connection Broker API** described for third-party session management. Do not substitute one API's ports or schema for the other. [Connection Broker API](https://docs.parallels.com/landing/ras-admin-guide/parallels-ras-21-administrators-guide/ras-connection-broker/enabling-connection-broker-api)
